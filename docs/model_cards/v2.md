# Defiende el servidor · v2 — revisión basada en los experimentos

Clasificador binario de conexiones de red (**0 = normal, 1 = ataque**) entrenado con las particiones publicadas de
UNSW-NB15. Es un producto del taller de MLOps de la Universidad Externado de Colombia (2026-II); su objetivo es
aprender a **versionar y recuperar** código, datos, experimentos y modelos, no desplegar un detector real.

- **Modelo de esta versión:** Revisión: modelo elegido por macro-F1 en validación entre todos los experimentos con modelo real. (experimento `E5_hist_gradient_boosting`, familia `hist_gradient_boosting`).
- **Umbral:** `0.654376`. Regla: `y_pred = 1 (ataque) si score_attack >= umbral; score_attack = probabilidad de ataque`.
- **Revisión:** esta card describe la revisión etiquetada `v2` de `brinez/defiende-el-servidor-unsw-nb15`; su SHA completo está en
  `evidencias/hf_publicacion.json` del repositorio de código.

## Propósito y usos

- **Uso previsto:** estudiar el ciclo de vida de un modelo (datos → experimento → versión → recuperación) y comparar v1 con v2.
- **Fuera de alcance:** proteger una red real. UNSW-NB15 es un benchmark histórico de laboratorio (2015) y no demuestra
  eficacia sobre tráfico actual. No debe usarse como único control de seguridad.

## Datos

- UNSW-NB15, particiones publicadas `UNSW_NB15_training-set.csv` (175.341 filas) y `UNSW_NB15_testing-set.csv` (82.332 filas),
  copia fijada de un mirror de terceros (los SHA-256 coinciden con los del enunciado, no están autenticados contra UNSW).
  Fuente oficial y condiciones de uso: https://research.unsw.edu.au/projects/unsw-nb15-dataset (uso académico; citar a Moustafa y Slay, 2015).
- **Entradas:** 42 variables (39 numéricas y 3 categóricas: `proto`, `service`, `state`). Se excluyen `label` (respuesta),
  `attack_cat` (revela la respuesta) e `id` (identifica filas; separa las clases solo por cómo viene ordenado el archivo).
- **Entrenamiento y validación:** salen solo del archivo de entrenamiento, con `StratifiedGroupKFold` (semilla 42); las
  filas con entradas idénticas siempre quedan juntas. El test no se usó para decidir nada de esta versión.

## Modelo, preprocesamiento y umbral

- Todo el preprocesamiento (log(1+x), escalado, codificación de categorías) está dentro del mismo objeto `Pipeline` y
  se ajustó **solo con entrenamiento**.
- **Umbral:** se eligió en validación con una regla declarada antes de ver resultados: *mayor recall con tasa de falsos positivos <= 5 %*.
- Denominadores cero: precision = 0 si no se emite ninguna alerta (TP+FP = 0); recall = 0 si no hay ataques reales (TP+FN = 0); FPR = 0 si no hay conexiones normales reales (FP+TN = 0). En validación y test ninguno de los denominadores es cero.

## Métricas de validación (35.067 filas)

Al umbral `0.654376` (el que usa esta versión):

| Métrica (clase positiva = ataque) | Validación |
|---|---|
| Recall de ataque | 95,42 % |
| Precision de ataque | 97,60 % |
| Tasa de falsos positivos (FPR) | 5,00 % |
| Macro-F1 | 0,9464 |
| Accuracy (complementaria) | 95,28 % |
| Matriz de confusión (VP / FP / FN / VN) | 22.773 / 560 / 1.094 / 10.640 |

ROC-AUC 0,9936 · PR-AUC 0,9970. Como referencia, con el umbral 0,5 la FPR sería 8,55 % y el recall 97,61 %.

## Qué cambió respecto a v1

Cambio único: el tipo de modelo (regresión logística → hist gradient boosting); preprocesamiento, particiones y regla de umbral son los mismos. v2 es el experimento con mayor macro-F1 en validación entre los de modelo real (`evidencias/seleccion_validacion.json`).

| Métrica (validación) | v1 | v2 | Diferencia | Efecto |
|---|---|---|---|---|
| Recall | 0,9121 | 0,9542 | +0,0420 | mejora |
| Precision | 0,9749 | 0,9760 | +0,0011 | mejora |
| FPR | 0,0500 | 0,0500 | +0,0000 | sin cambio |
| Macro-F1 | 0,9157 | 0,9464 | +0,0307 | mejora |
| Accuracy | 0,9242 | 0,9528 | +0,0286 | mejora |

**Qué mejora:** recall (+0,0420) y macro-F1, con la misma FPR de 5 %: se detectan más ataques sin aumentar las falsas alarmas.  
**Qué empeora o se acepta:** ninguna métrica de validación empeora. El modelo pasa de 324 KB a 2.852 KB, el entrenamiento de 6,7 s a 14,5 s y se pierde la lectura directa de coeficientes. La FPR queda en 5 % por construcción (es la regla del umbral), así que ahí no se espera ni se mide mejora.  
**Errores que se aceptan:** 1.094 ataques no detectados y 560 falsas alarmas en las 35.067 filas de validación. La mejora en validación no garantiza la misma mejora en el test, donde la distribución es distinta.

## Cómo usarlo

```python
import json
import pandas as pd
import skops.io as sio
from huggingface_hub import snapshot_download

carpeta = snapshot_download("brinez/defiende-el-servidor-unsw-nb15", revision="v2")   # o el SHA completo de la revisión
cfg = json.load(open(f"{carpeta}/config.json", encoding="utf-8"))
modelo = sio.load(f"{carpeta}/modelo.skops", trusted=cfg["tipos_confiables_skops"])

df = pd.read_csv("conexiones.csv")                                  # mismas 42 columnas de entrada
score_attack = modelo.predict_proba(df[cfg["columnas_entrada"]])[:, 1]
y_pred = (score_attack >= cfg["umbral"]).astype(int)                # 1 = ataque
```

`trusted` lista únicamente tipos internos de scikit-learn (`sklearn.ensemble._hist_gradient_boosting.predictor.TreePredictor`); revísalos antes de cargar.

## Limitaciones

- Benchmark histórico y sintético: no generaliza por sí mismo a una red actual.
- La validación (partición aleatoria agrupada del mismo archivo) es más favorable que el test publicado: allí las entradas
  son en su gran mayoría distintas a las de entrenamiento, así que la tasa de falsos positivos del test puede ser mayor que la de validación.
- Hay filas con entradas idénticas y etiquetas contradictorias; ningún modelo con estas variables puede acertarlas todas.
- La FPR objetivo (5 %) se fijó en validación; en producción cada falsa alarma tiene un costo operativo que aquí no se modela.
- Los SHA-256 coinciden con los del enunciado, pero el mirror de origen no está autenticado contra el archivo oficial de UNSW.
